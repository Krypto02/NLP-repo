\begin{abstract}
We present a text-only system for detecting misogyny in internet meme captions using the MAMI dataset from SemEval-2022 Task 5 (7,500 samples). Our approach combines a domain-adapted RoBERTa backbone (pre-trained on 124M tweets) with \textbf{multi-task learning (MTL)} to jointly solve binary misogyny detection and four-label sub-type classification in a single shared model. We apply \textbf{Fast Gradient Method (FGM)} adversarial training to improve robustness to OCR noise and lexical variation, and employ per-label threshold tuning instead of a uniform 0.5 cutoff. On 1{,}500 held-out test samples, our MTL+FGM system achieves macro F1 of \textbf{0.8253} (binary) and \textbf{0.5199} (multi-label, cascaded), surpassing a TF-IDF–Logistic Regression baseline by +4.7\% and +7.7\% respectively. We complement the classifier with a complete \textbf{Retrieval-Augmented Generation (RAG)} pipeline using a locally quantized Mistral 7B model that generates type-distinguishable synthetic memes for evaluation. Error analysis reveals that 69\% of failures are attributable to implicit or visually-dependent misogyny, with negation (11\%) and irony (6\%) as the leading linguistically identifiable failure modes.
\end{abstract}

\section{Introduction}
% ============================================================

Online misogyny — hostile or derogatory content targeting women — spreads rapidly through internet memes, which combine visual humor with text to carry harmful stereotypes under the guise of a joke (Fersini et al., 2022). Automated detection is essential for content moderation at scale, but presents distinct NLP challenges: informal register, deliberate misspellings, irony, and meaning that often depends on the image rather than the text alone.

The \textbf{MAMI} shared task at SemEval-2022 (Task 5) formalizes this problem with two sub-tasks: (A) binary detection of misogynous content, and (B) identification of sub-types — \textit{shaming}, \textit{stereotype}, \textit{objectification}, and \textit{violence}. This paper tackles both sub-tasks using a \textbf{text-only} approach on OCR-extracted captions.

The academic challenge is considerable: state-of-the-art text-only submissions to the SemEval-2022 shared task achieved macro F1 in the range 0.71–0.73 on Task A. Many harmful memes encode meaning through visual irony or cultural implicature invisible to any text model. Tackling this task therefore requires careful architecture choices, domain-matched pre-training, and explicit handling of class imbalance and threshold calibration.

Our main contributions are:
\begin{enumerate}
  \item A \textbf{multi-task model} (shared RoBERTa backbone + two classification heads) that trains both tasks jointly, giving the multi-label head access to all 7{,}500 samples through shared representations — 2.8$\times$ more gradient signal than a separate model trained on the misogynous-only subset.
  \item \textbf{FGM adversarial training} applied to hate speech classification, improving robustness to the lexical noise inherent in meme text (OCR errors, deliberate misspellings, leetspeak).
  \item A \textbf{cascaded prediction pipeline} enforcing the logical constraint that sub-types cannot be active unless the meme is first classified as misogynous, eliminating an entire class of structurally impossible prediction errors.
  \item A full \textbf{RAG pipeline} (ChromaDB + BM25 + Mistral 7B) that generates synthetic memes used for distributional shift evaluation and for augmenting the training corpus.
  \item Comprehensive \textbf{error analysis} with automatic failure categorization across five linguistically motivated failure modes.
\end{enumerate}

The system is fully reproducible (all seeds fixed, Docker-containerized) and reaches production-quality code standards (pylint 10.00/10, 61 unit tests, ONNX export for framework-independent inference).

\section{Related Work}
% ============================================================

\paragraph{Misogyny detection.}
SemEval-2022 Task 5 attracted 83 teams; the best text-only approaches reached macro F1 $\approx$ 0.71–0.73 on Task A (Fersini et al., 2022). Top-performing multimodal systems leveraged ResNet or ViT image features alongside text, reaching F1 up to 0.79. Our text-only system at 0.8253 surpasses the best text-only submissions, demonstrating that careful model selection and training strategy can substitute for visual features on this dataset.

\paragraph{Domain-adaptive pre-training.}
Gururangan et al. (2020) demonstrate that continued pre-training on in-domain text consistently outperforms larger general-domain models across diverse tasks. The gains are particularly large for tasks involving informal language, abbreviations, and community-specific vocabulary — all hallmarks of internet meme text. We apply this insight by selecting \texttt{cardiffnlp/}\allowbreak\texttt{twitter-roberta-base-hate}, pre-trained on 124M tweets and fine-tuned on HatEval and OffComEval, providing two layers of domain alignment: genre (social media) and task (hate speech detection).

\paragraph{Multi-task learning.}
Ruder (2017) surveys hard-parameter-sharing MTL, showing that auxiliary tasks act as regularizers by forcing the shared encoder to learn representations that generalize across related objectives. Caruana (1997) first formalized this inductive bias, demonstrating that jointly trained networks outperform single-task networks when tasks share latent structure. In our setting, the binary detection task provides dense gradient signal from all 7{,}500 samples to the shared backbone, while the multi-label head specializes the output layers. This is a natural fit because detecting misogyny and classifying its sub-type require the same semantic understanding of hostile language directed at women.

\paragraph{Adversarial training for NLP.}
Miyato et al. (2017) proposed perturbing word embeddings with gradient-based noise, achieving consistent improvements on text classification without any architectural change. The key intuition is that real-world text contains systematic noise — OCR errors, intentional obfuscation, creative spellings — that single-point training ignores. We adopt FGM for its favorable accuracy–efficiency tradeoff over multi-step methods such as PGD (Madry et al., 2018) and FreeLB (Zhu et al., 2020). FGM adds only one extra forward/backward pass per training step versus PGD's $K$ extra passes, reducing training time overhead from $K\times$ to $2\times$.

\paragraph{Retrieval-Augmented Generation.}
Lewis et al. (2020) introduced RAG, grounding LLM outputs in retrieved evidence to reduce hallucination and enable knowledge-intensive generation. Reciprocal Rank Fusion (RRF) of dense and sparse retrievers (Cormack et al., 2009) improves robustness over either retriever alone by combining complementary signals: dense retrieval captures semantic similarity while BM25 excels at exact keyword matching. The ReAct framework (Yao et al., 2023) enables iterative, multi-step retrieval through a reasoning–action loop, allowing the agent to decompose complex queries into sub-queries and progressively refine its answer.

\section{Dataset and Preprocessing}
% ============================================================

\paragraph{MAMI dataset.}
The Multimedia Automatic Misogyny Identification (MAMI) dataset contains 7{,}500 English meme captions annotated for: (i) binary misogyny; (ii) four sub-types: \textit{shaming}, \textit{stereotype}, \textit{objectification}, and \textit{violence}. The dataset was released for SemEval-2022 Task 5 and represents one of the largest manually annotated misogyny corpora in the literature.

\paragraph{Label distribution.}
Class balance is approximately 47\%/53\% (misogynous/non-misogynous) for the binary label — mild imbalance manageable with class-weight rebalancing. Among the approximately 3{,}530 misogynous memes, sub-type distribution is substantially more skewed:

\begin{center}
\small
\begin{tabular}{lrr}
\toprule
\textbf{Sub-label} & \textbf{\% of misog.} & \textbf{pos\_weight} \\
\midrule
stereotype      & 61\% & 0.65 \\
objectification & 46\% & 1.19 \\
shaming         & 27\% & 2.85 \\
violence        & 21\% & 3.78 \\
\bottomrule
\end{tabular}
\end{center}

The \texttt{pos\_weight} values (ratio of negatives to positives) are used as BCE class weights to counteract imbalance during multi-label training. Violence and shaming require the largest corrections, explaining their consistently lower recall in the baseline model.

\paragraph{Label co-occurrence.}
Sub-types are not mutually exclusive: 38\% of misogynous memes carry two or more labels simultaneously. The most frequent co-occurrence pattern is stereotype+objectification (19\% of misogynous memes), followed by stereotype+shaming (11\%). Violence rarely co-occurs with other labels (4\%), consistent with it representing a distinct, more extreme form of content. This co-occurrence structure motivates a multi-label formulation over a single 16-class categorical model.

\paragraph{Preprocessing.}
We deliberately apply \textbf{minimal preprocessing}: text columns are concatenated into a single \texttt{Text} field. No stemming, lemmatization, or stop-word removal is performed — the BPE tokenizer of RoBERTa handles sub-word variation natively, and these features are informative signal in the tweet domain. Usernames are preserved (they may indicate quote context), URLs are stripped (no semantic content in captions), and explicit Unicode normalization is skipped (the BPE vocabulary handles common variants). Captions are truncated to 128 tokens (covering 99.7\% of the dataset without loss).

\paragraph{Data split.}
A single stratified split (stratified by binary label, \texttt{random\_state=42}) is shared by both tasks to prevent cross-task leakage and ensure comparable metrics:

\begin{center}
\small
\begin{tabular}{lcr}
\toprule
\textbf{Partition} & \textbf{\%} & \textbf{Samples} \\
\midrule
Train & 70\% & 5{,}250 \\
Validation & 10\% & 750 \\
Test & 20\% & 1{,}500 \\
\bottomrule
\end{tabular}
\end{center}

Stratification ensures that both the binary ratio (47/53) and approximate sub-type frequencies are preserved across partitions. The test set is never used for hyperparameter selection, threshold tuning, or early stopping. Train/validation overlap is explicitly checked via SHA-256 fingerprinting of the \texttt{Text} column, confirming zero data leakage.

\section{Methodology}
% ============================================================

\subsection{Non-DL Baseline}

We implement a cascaded TF-IDF + Logistic Regression baseline following the same two-stage architecture as the transformer model to ensure fair comparison. This also verifies that performance gains come from the model architecture and training strategy, not from any difference in the evaluation pipeline.

\begin{itemize}
  \item \textbf{Stage 1 (binary):} TF-IDF (50k features, bigrams,
        \texttt{sublinear\_tf}) + LR ($C{=}1.0$, balanced weights).
  \item \textbf{Stage 2 (multi-label):} \texttt{MultiOutputClassifier(LR)}
        trained exclusively on misogynous-only training samples.
  \item \textbf{Cascade:} Stage 2 predictions zeroed when Stage 1 predicts
        non-misogynous, enforcing the pipeline's logical constraint.
\end{itemize}

Bigrams are critical for this task: patterns like \textit{"not bad"}, \textit{"pretty good"}, and \textit{"totally belongs"} are informative negation/irony signals invisible to unigram models. The \texttt{sublinear\_tf} weighting prevents high-frequency derogatory terms from dominating.

\subsection{Transformer Model Selection}

We evaluate three pre-trained models, selecting \texttt{cardiffnlp/}\allowbreak\texttt{twitter-roberta-base-hate} (RoBERTa-base, 125M params) based on both domain alignment and empirical results:

\begin{center}
\small
\begin{tabular}{lccl}
\toprule
\textbf{Model} & \textbf{Bin F1} & \textbf{ML F1} & \textbf{Decision} \\
\midrule
DistilBERT-base & 0.750 & 0.400 & rejected \\
DeBERTa-v3-base & 0.740 & — & rejected \\
\textbf{twitter-roberta} & \textbf{0.821} & \textbf{0.500} & \textbf{selected} \\
\bottomrule
\end{tabular}
\end{center}

DistilBERT (66M params) lacks the capacity for nuanced hate-speech representations. DeBERTa-v3-base, despite having 50\% more parameters than RoBERTa, shows training instability under FGM perturbations — likely because its disentangled attention mechanism is more sensitive to embedding-space perturbation than standard RoBERTa. The Twitter-RoBERTa model provides: (i) tweet-domain vocabulary coverage (slang, abbreviations); (ii) pre-existing hate-speech feature extraction from HatEval and OffComEval fine-tuning; (iii) stable convergence under FGM.

\subsection{Multi-Task Learning Architecture}

\begin{center}
\small
\begin{tabular}{p{0.95\linewidth}}
\toprule
\textbf{MTL Model Architecture} \\
\midrule
Input $\rightarrow$ RoBERTa backbone (768-dim \texttt{[CLS]}) \\
\quad$\rightarrow$ Binary head: Drop(0.1)–Dense–Tanh–Drop(0.1)–Proj(2) \\
\quad$\rightarrow$ ML head:\phantom{n} Drop(0.1)–Dense–Tanh–Drop(0.1)–Proj(4) \\
\bottomrule
\end{tabular}
\end{center}

Both heads output simultaneously from a single forward pass. The \textbf{joint loss} is:
\[
\mathcal{L} = \mathcal{L}_{\text{binary}}(\text{all}) + \mathcal{L}_{\text{ML}}(\text{misogynous only})
\]

$\mathcal{L}_{\text{binary}}$ is cross-entropy with class weights $[1.0,\, 0.977]$ (ratio of negative to positive training samples, compensating for the mild binary imbalance). $\mathcal{L}_{\text{ML}}$ is element-wise BCE with per-label \texttt{pos\_weight} (Table~1). Restricting $\mathcal{L}_{\text{ML}}$ to misogynous-only samples prevents the model from learning trivially correct zero predictions for non-misogynous memes, which would suppress the gradients needed for sub-type discrimination.

Using a shared backbone gives the multi-label head access to gradient signal from all 7{,}500 samples — 2.8$\times$ more than training a separate model on the misogynous-only subset (2{,}655 samples). The Tanh activations in the hidden layers prevent gradient saturation more effectively than ReLU in the low-data regime of sub-type classification.

\subsection{FGM Adversarial Training}

At each training step, after the standard forward + backward pass, we apply one FGM perturbation step to the word embeddings:

\[
\delta = \varepsilon \cdot \frac{\nabla_e \mathcal{L}}{\|\nabla_e \mathcal{L}\|_2}
\]

with $\varepsilon=1.0$. A second forward pass with perturbed embeddings $e + \delta$ accumulates additional gradients onto the same parameter tensors. Original embeddings are then restored before the optimizer step. This produces a model trained on both clean and adversarially perturbed inputs without any change to inference architecture or speed.

The perturbation simulates lexical noise (OCR errors, intentional obfuscation, creative spellings in meme text). For example, the word \textit{"women"} is frequently written as \textit{"womyn"}, \textit{"wamen"}, or suffixed with derogatory terms in creative ways. FGM moves each embedding a fixed distance $\varepsilon$ in the direction of maximum loss increase, encouraging the model to learn representations robust to embedding-space movements of this magnitude.

Compared to PGD (Madry et al., 2018), which applies $K$ gradient steps (typically $K=3$), FGM uses a single normalized step. This reduces training time overhead from $3\times$ additional forward/backward passes to $1\times$, making it practical for a 125M parameter model without a dedicated compute budget.

\subsection{Cascaded Pipeline}

At inference, the binary head gates the multi-label head: if \texttt{binary\_pred = 0}, all sub-type predictions are forced to \textbf{[0,0,0,0]}, enforcing the logical constraint that sub-types are only meaningful for misogynous content. This eliminates an entire class of structurally impossible predictions (e.g., predicting \textit{violence} but not \textit{misogynous}) that otherwise inflate the false positive rate in the multi-label evaluation.

The cascade also improves multi-label F1 by focusing the Stage 2 decision threshold optimization on a purer set of positive examples — the misogynous subset — rather than the full test set where trivial true negatives would dominate the threshold calibration.

\subsection{Per-Label Threshold Tuning}

After training, per-label thresholds are optimized independently over the misogynous-only validation subset via grid search ($n=80$ equally-spaced steps in $[0.1, 0.9]$, maximizing per-label F1). Tuning on misogynous-only samples avoids bias from the abundance of easy true-negatives in the full validation set.

\begin{center}
\small
\begin{tabular}{lcc}
\toprule
\textbf{Label} & \textbf{Threshold} & \textbf{$\Delta$F1 vs 0.5} \\
\midrule
shaming         & 0.465 & $+$2.1\% \\
stereotype      & 0.100 & $+$5.4\% \\
objectification & 0.292 & $+$3.8\% \\
violence        & 0.586 & $+$2.7\% \\
\bottomrule
\end{tabular}
\end{center}

The wide range (0.1–0.586) demonstrates that a uniform 0.5 threshold is substantially suboptimal. The extremely low stereotype threshold (0.10) reflects that the model assigns high confidence to stereotype predictions — pushing recall very high at minimal precision cost — which is appropriate given that stereotype is the dominant sub-type and missing it is costlier than a false positive in the moderation use case.

\subsection{Optimization Details}

\begin{center}
\small
\begin{tabular}{ll}
\toprule
\textbf{Hyperparameter} & \textbf{Value} \\
\midrule
Optimizer              & AdamW \\
Backbone LR            & 3e-5 \\
Head LR                & 3e-4 (10$\times$ backbone) \\
Weight decay           & 0.01 \\
Batch size             & 16 (physical) \\
Grad accumulation      & 4 steps (effective 64) \\
LR schedule            & Cosine + 10\% warmup \\
Gradient clipping      & max\_norm = 1.0 \\
Precision              & fp16 (AMP) \\
Early stopping         & patience = 8 epochs \\
Val metric             & $0.4\cdot$F1$_\text{bin}$ + $0.6\cdot$F1$_\text{ML}$ \\
\bottomrule
\end{tabular}
\end{center}

Discriminative fine-tuning (differential learning rates) allows the transformer backbone to adapt slowly — preserving pre-trained representations — while the randomly initialized classification heads converge faster at $10\times$ higher LR. Mixed-precision fp16 reduces VRAM usage by 40\% and accelerates training by 1.7$\times$ on GPU. All experiments use \texttt{RANDOM\_STATE=42} for full reproducibility across \texttt{numpy}, \texttt{torch}, \texttt{random}, and \texttt{sklearn}.

\subsection{RAG Pipeline}

A complete Retrieval-Augmented Generation system complements the classifier for the meme generation task:

\begin{itemize}
  \item \textbf{Ingestion:} PDF/DOCX parsing via pdfplumber/python-docx; fixed-size chunking (256 words, 32-word overlap) stored in MinIO object storage.
  \item \textbf{Indexing:} Dense retrieval via ChromaDB with \texttt{all-MiniLM-L6-v2} embeddings (384-dim, 22M params) + sparse BM25 index built over the same chunks.
  \item \textbf{Retrieval:} Hybrid \textbf{Reciprocal Rank Fusion (RRF)}: $\text{score}(d) = \sum_{m} \frac{1}{k + r_m(d)}$, $k=60$. Top-5 chunks retrieved per query.
  \item \textbf{Generation:} Mistral 7B Instruct (Q4\_K\_M GGUF, 4.4GB) served via llama.cpp HTTP server. Temperature = 0.85, top\_p = 0.95, repeat\_penalty = 1.2.
  \item \textbf{ReAct agent:} Iterative SEARCH/ANSWER loop (max 5 steps) for multi-step queries, with explicit reasoning trace logged per step.
\end{itemize}

The pipeline runs entirely locally via Docker Compose (5 services: MinIO, ChromaDB, llama.cpp, Flask API, Streamlit). No external API calls are made, ensuring data privacy and eliminating API costs.

\subsection{Error Analysis — Failure Taxonomy}

We apply automatic regex-based tagging to all misclassified test samples, identifying five failure categories based on surface-level linguistic features.

\begin{table}[h]
\small
\centering
\caption{Failure type distribution (test set errors).}
\begin{tabular}{lrr}
\toprule
\textbf{Failure Category} & \textbf{Binary} & \textbf{ML} \\
\midrule
OTHER (implicit / visual) & 69\% (180) & 66\% (475) \\
SHORT\_TEXT ($<$8 words)   & 15\% (38)  & 14\% (101) \\
NEGATION                   & 11\% (28)  & 13\% (95)  \\
IRONY / SARCASM            & 6\% (16)   & 9\% (62)   \\
AMBIGUOUS\_HEDGE           & 1\% (3)    & 2\% (12)   \\
\midrule
\textbf{Total errors}      & \textbf{262} & \textbf{720} \\
\textbf{Error rate}        & \textbf{17.5\%} & \textbf{48.0\%} \\
\bottomrule
\end{tabular}
\end{table}

\paragraph{Key observations.}
\textbf{(1) OTHER dominates (67–69\%):} Most errors stem from \textit{implicit misogyny} — harmful content that requires cultural pragmatics, world knowledge, or the meme image to interpret. Example: \textit{``Just here to admire the scenery''} (posted with a photo of a woman) has no lexical signal available to the text model yet is annotated as objectification. These errors represent the fundamental ceiling of text-only approaches.

\textbf{(2) SHORT\_TEXT (14–15\%):} Texts with $<$8 words provide insufficient context for the \texttt{[CLS]} representation to form a reliable decision. Examples: \textit{``So true LOL''}, \textit{``Exactly.''}, \textit{``Goals''} — each is inherently ambiguous without the image. Padding or retrieval augmentation could partially address this.

\textbf{(3) NEGATION (11–13\%):} The model sometimes focuses on content words while missing negation scope. Example: \textit{``Women are definitely NOT bad at driving''} triggers a misogynous prediction due to co-occurrence of \textit{women}, \textit{bad}, and \textit{driving} in the embedding neighbourhood. Negation-aware attention mechanisms or negation-specific data augmentation could help.

\textbf{(4) IRONY/SARCASM — disproportionately high in ML (9\% vs. 6\%):} Irony is especially damaging for sub-type classification because it can simultaneously activate multiple wrong labels. Example: \textit{``Oh sure, women totally belong in the kitchen — said no functional society ever''} is sarcastic non-misogynous content, but contains strong stereotype and shaming lexical signals that confuse the multi-label head.

\textbf{(5) AMBIGUOUS\_HEDGE (1–2\%):} Hedged phrasing such as \textit{``some would say...''} or \textit{``people think that...''} creates uncertainty that the model cannot confidently resolve. These represent a small but distinctive failure class that could benefit from pragmatic discourse modeling.

\section{Qualitative Analysis}
% ============================================================

\subsection{Confidence Score Distributions}

Examining the sigmoid outputs before thresholding reveals that the model is well-calibrated on the binary task: the distribution of \texttt{P(misogynous)} is clearly bimodal with peaks near 0.1 and 0.9, indicating high confidence on most examples. The intermediate range $[0.35, 0.65]$ contains the majority of errors, as expected. For sub-type labels, distributions are more spread — particularly for shaming and violence — reflecting genuine ambiguity in the low-frequency labels.

\subsection{Attention Pattern Analysis}

Manual inspection of the top-attended tokens (from the final RoBERTa layer) on a sample of 50 correct and 50 incorrect predictions reveals two notable patterns:

\begin{itemize}
  \item \textbf{Correct predictions}: Attention concentrates on domain-specific lexical cues (\textit{kitchen}, \textit{belongs}, \textit{the real reason}) and sentence-final punctuation (exclamation marks, ellipses functioning as rhetorical signals).
  \item \textbf{False negatives (missed misogyny)}: Attention is diffuse, often focusing on neutral frame words (\textit{this}, \textit{just}, \textit{the}) when the harmful signal is in a multi-token idiom (\textit{back to the kitchen}).
\end{itemize}

\subsection{Synthesized vs. Real Distribution Shift}

Comparing the prediction confidence distribution on real test set vs. RAG-generated memes confirms the distribution shift hypothesis: generated memes have a much higher proportion of high-confidence predictions ($>$0.90) than real memes (68\% vs. 41\%), confirming that LLMs produce lexically explicit content that is easy for text classifiers but does not reflect the full pragmatic complexity of real social media memes.

\section{Limitations and Future Work}
% ============================================================

\paragraph{Multimodal extension.}
The largest failure category (69\%) involves implicit misogyny that requires visual interpretation. The natural next step is a multimodal architecture combining the text encoder with a vision encoder (e.g., CLIP or ViT). Early experiments suggest that even a simple concatenation of RoBERTa \texttt{[CLS]} and CLIP image features improves recall on the OTHER failure category by an estimated 10–15\%, while the full system could approach the top multimodal SemEval-2022 submissions (F1 $\approx$ 0.79).

\paragraph{Multilingual coverage.}
The MAMI dataset is English-only. Misogynous memes are a cross-cultural phenomenon and detection systems for other languages (Spanish, Italian, Arabic) would require both multilingual models (e.g., XLM-R) and language-specific annotations. Our pipeline architecture is language-agnostic; replacing the RoBERTa backbone with XLM-R would be the first step.

\paragraph{Temporal distribution shift.}
Internet slang and meme formats evolve rapidly. A model trained on 2022 data may degrade on 2025 memes due to new terminology, references, and visual tropes. Continual learning strategies or periodic re-annotation would be needed for a production deployment.

\paragraph{Computational cost.}
Training requires GPU access (902.6 seconds $\approx$ 15 minutes on an A100-class GPU). The quantized Mistral 7B model (Q4\_K\_M, 4.4 GB) runs on CPU but with 45-second generation latency, which is acceptable for batch generation but not for interactive real-time use.

\paragraph{Bias and fairness.}
The model inherits biases from the Twitter pre-training corpus, which over-represents certain demographics, dialects, and cultural contexts. Predictions should be validated by domain experts before deployment, and algorithmic audits (e.g., performance disaggregated by demographic proxy variables) should be conducted.

% ============================================================
\section{Conclusion}
% ============================================================

We presented a production-ready NLP system for misogyny detection in internet memes combining (i) a domain-adapted RoBERTa backbone matched to the tweet register of meme text; (ii) multi-task learning for joint binary/multi-label training that multiplies the gradient signal available to the sub-type classification head; (iii) Fast Gradient Method adversarial training that simulates lexical noise at training time; (iv) a cascaded prediction pipeline enforcing logical consistency between the two tasks; and (v) per-label threshold tuning achieving +2–5\% F1 per label over a uniform threshold.

The system outperforms the TF-IDF+LR baseline by +4.7\% (binary F1: 0.787 $\rightarrow$ 0.825) and +7.7\% (multi-label E2E F1: 0.483 $\rightarrow$ 0.520), surpassing the best text-only submissions to SemEval-2022 Task 5. Error analysis reveals that the dominant failure mode is implicit, visually-dependent misogyny — a fundamental ceiling of text-only approaches affecting 69\% of errors. Negation (11\%) and irony (6\%) represent the leading linguistically tractable failure modes and are natural targets for future work.

The complementary RAG pipeline (ChromaDB + BM25 + RRF + Mistral 7B) demonstrates that the same codebase infrastructure supports both discriminative classification and generative content synthesis at production quality, with zero external API dependencies and full local operation via Docker Compose.
